# 模块八：AI 识别模块 (ai.cpp)

## 1. 模块定位

`ai.cpp` 负责调用阿里云 DashScope（兼容 OpenAI 格式）的视觉语言模型进行垃圾分类识别。模块支持两种图片输入方式：Base64 直传（调试保留）和 OBS 预签名 URL（主流程使用）。

文件位置：`src/ai.cpp`（239行） | 头文件：`include/ai.h`

---

## 2. API 配置

### 2.1 DashScope 兼容模式

```cpp
// include/secrets.h
#define AI_API_ENDPOINT "https://dashscope.aliyuncs.com/compatible-mode"
#define AI_API_KEY       "sk-xxx"
#define AI_MODEL         "qwen3.5-flash"
```

DashScope 的 `/compatible-mode` 端点提供与 OpenAI Chat Completions API 兼容的接口格式。

### 2.2 URL 自动拼接

```cpp
static String buildAIRequestUrl() {
    String base = String(AI_API_ENDPOINT);
    base.trim();

    // 兼容多种配置格式：
    if (base.endsWith("/chat/completions"))     return base;
    if (base.endsWith("/v1"))                   return base + "/chat/completions";
    if (base.endsWith("/v1/"))                  return base + "chat/completions";
    if (base.endsWith("/compatible-mode"))       return base + "/v1/chat/completions";
    if (base.endsWith("/compatible-mode/"))      return base + "v1/chat/completions";
    if (base.endsWith("/"))                      return base + "chat/completions";
    return base + "/chat/completions";
}
```

**设计意图**：用户在 `secrets.h` 中配置的 endpoint 格式可能不同（有的以 `/v1` 结尾，有的以 `/compatible-mode` 结尾），此函数自动拼接正确的完整路径，避免配置错误。

### 2.3 超时配置

```cpp
static const uint32_t AI_CONNECT_TIMEOUT_MS = 15000;   // 连接超时 15秒
static const uint16_t AI_RESPONSE_TIMEOUT_MS = 65000;  // 响应超时 65秒
```

AI 模型的响应时间受多种因素影响（图片复杂度、服务器负载），65 秒的宽松超时确保不会过早放弃。

## 3. AI 请求构建

### 3.1 提示词设计

```cpp
String buildPrompt() {
    return "请识别这张图片中的垃圾类型。这是一个二分类任务：可回收垃圾或其他垃圾。\n\n"
           "可回收垃圾包括：纸张、塑料瓶、玻璃瓶、金属罐、纸箱等。\n"
           "其他垃圾包括：食物残渣、用过的纸巾、陶瓷碎片、烟头等。\n\n"
           "请以JSON格式返回识别结果，格式如下：\n"
           "{\n"
           "  \"type\": \"recyclable\" 或 \"other\",\n"
           "  \"confidence\": 0.0-1.0之间的置信度数值\n"
           "}\n\n"
           "请只返回JSON，不要包含其他文字。\n/no_think";
}
```

**提示词设计分析**：

1. **任务定义**：明确告知模型这是二分类任务
2. **类别定义**：列举典型垃圾物品帮助模型理解边界
   - 可回收垃圾列举：纸张、塑料瓶、玻璃瓶、金属罐、纸箱
   - 其他垃圾列举：食物残渣、纸巾、陶瓷、烟头
3. **输出格式约束**：要求严格的 JSON 格式，包含 `type` 和 `confidence` 两个字段
4. **防额外输出**："请只返回JSON，不要包含其他文字"——避免模型输出解释性文字干扰解析
5. **`/no_think` 指令**：DashScope Qwen3.5 系列默认开启思考模式（reasoning），此指令显式关闭，减少响应时间和 token 消耗

### 3.2 请求体构造

```cpp
JsonDocument doc;
doc["model"] = AI_MODEL;  // "qwen3.5-flash"
doc["messages"][0]["role"] = "user";
doc["messages"][0]["content"][0]["type"] = "text";
doc["messages"][0]["content"][0]["text"] = buildPrompt();
doc["messages"][0]["content"][1]["type"] = "image_url";
doc["messages"][0]["content"][1]["image_url"]["url"] = imageUrl;  // 预签名URL
doc["max_tokens"] = 80;
doc["enable_thinking"] = false;
doc["thinking_budget"] = 128;

String requestBody;
serializeJson(doc, requestBody);
```

### 3.3 请求体对比

| 方案 | 请求体大小 | 说明 |
|------|-----------|------|
| Base64 直传 | ~80KB | `data:image/jpeg;base64,/9j/4AAQ...` |
| OBS 预签名 URL | ~2KB | `https://bucket.obs...?AccessKeyId=...&Signature=...` |

**预签名 URL 方案的优势**：
- 请求体减小约 40 倍
- HTTP 传输时间从数秒降低到毫秒级
- 减少 ESP32 的 JSON 序列化内存压力
- AI API 服务器下载图片比接收 Base64 更高效

## 4. HTTP 请求执行

### 4.1 performAIRequest()

```cpp
bool performAIRequest(const String& imageUrl, GarbageType& type, float& confidence) {
    HTTPClient http;
    String url = buildAIRequestUrl();

    // 配置 HTTP 客户端
    http.begin(url);
    http.addHeader("Content-Type", "application/json");
    http.addHeader("Authorization", "Bearer " + String(AI_API_KEY));
    http.addHeader("Connection", "close");
    http.setConnectTimeout(AI_CONNECT_TIMEOUT_MS);   // 15秒
    http.setTimeout(AI_RESPONSE_TIMEOUT_MS);          // 65秒

    // 构造请求体（见上文）
    JsonDocument doc;
    // ... JSON 构造 ...

    // 发送 POST 请求
    int httpResponseCode = http.POST(requestBody);

    // 错误处理
    if (httpResponseCode != 200) {
        if (httpResponseCode > 0) {
            String response = http.getString();
            ERROR_PRINTF("响应内容: %s\n", response.c_str());
        } else {
            ERROR_PRINTF("HTTP错误: %s\n",
                         http.errorToString(httpResponseCode).c_str());
        }
        http.end();
        return false;
    }

    // 获取并解析响应
    String responseBody = http.getString();
    bool success = parseAIResponse(responseBody, type, confidence);

    http.end();
    return success;
}
```

**使用 HTTPClient 而非 WiFiClientSecure**：
- HTTPClient 对 HTTPS 的支持更好，自动处理 SSL 握手
- `http.begin(url)` 自动识别 https:// 前缀并配置 SSL
- 设置 `Connection: close` 避免 keep-alive 超时问题

## 5. 响应解析

### 5.1 parseAIResponse() — 两级 JSON 解析

AI 返回的响应包含两层 JSON：
1. **外层**：OpenAI 格式的 Chat Completion 响应结构
2. **内层**：模型返回的内容本身是 JSON 字符串

```json
// 外层结构（API响应）
{
  "choices": [{
    "message": {
      "content": "{\"type\": \"recyclable\", \"confidence\": 0.95}"
    }
  }]
}
```

```cpp
bool parseAIResponse(const String& response, GarbageType& type, float& confidence) {
    // ===== 第一级解析：提取 choices[0].message.content =====
    JsonDocument doc;
    DeserializationError error = deserializeJson(doc, response);
    if (error) { return false; }

    const char* content = doc["choices"][0]["message"]["content"];
    if (content == NULL) { return false; }

    // ===== 第二级解析：解析 content 中的 JSON =====
    JsonDocument contentDoc;
    error = deserializeJson(contentDoc, content);

    if (error) {
        // ===== 容错处理：JSON解析失败时进行文本匹配 =====
        if (strstr(content, "recyclable") != NULL) {
            type = GARBAGE_RECYCLABLE;
            confidence = 0.7;
            return true;
        } else if (strstr(content, "other") != NULL) {
            type = GARBAGE_OTHER;
            confidence = 0.7;
            return true;
        }
        return false;
    }

    // ===== 提取结果 =====
    const char* typeStr = contentDoc["type"];
    confidence = contentDoc["confidence"] | 0.8;  // 默认置信度 0.8

    if (typeStr == NULL) { return false; }

    if (strcmp(typeStr, "recyclable") == 0) {
        type = GARBAGE_RECYCLABLE;
    } else if (strcmp(typeStr, "other") == 0) {
        type = GARBAGE_OTHER;
    } else {
        return false;
    }

    return true;
}
```

### 5.2 容错机制

AI 模型的输出不完全可控，因此设计了多层容错：

1. **JSON 解析失败**：尝试在 content 字符串中搜索 "recyclable" 或 "other" 关键词
2. **默认置信度**：JSON 解析中缺少 `confidence` 字段时，使用 0.8 作为默认值（`contentDoc["confidence"] | 0.8`）
3. **严格类型检查**：`typeStr` 必须是 `"recyclable"` 或 `"other"`，否则返回失败

### 5.3 `|` 运算符作为默认值

`contentDoc["confidence"] | 0.8` 利用了 ArduinoJson 的一个特性：当字段不存在时，`operator|` 返回右侧的默认值。

## 6. 双接口设计

### 6.1 recognizeGarbage() — Base64 直传（调试保留）

```cpp
bool recognizeGarbage(const uint8_t* imageData, size_t imageDataSize,
                      GarbageType& type, float& confidence) {
    String base64Image = encodeImageToBase64(imageData, imageDataSize);
    String imageUrl = "data:image/jpeg;base64," + base64Image;
    return performAIRequest(imageUrl, type, confidence);
}
```

此接口保留用于调试——当 OBS 不可用时可以直接传 Base64 图片测试 AI 识别。不用于主流程。

### 6.2 recognizeGarbageByUrl() — URL 方式（主流程）

```cpp
bool recognizeGarbageByUrl(const char* imageUrl, GarbageType& type, float& confidence) {
    if (imageUrl == NULL || strlen(imageUrl) == 0) {
        return false;
    }
    return performAIRequest(String(imageUrl), type, confidence);
}
```

这是状态机 `STATE_RECOGNIZE` 调用的接口，传入 OBS 预签名 URL。

## 8. 关键设计决策

1. **OBS URL 优于 Base64**：请求体大小从 ~80KB 降至 ~2KB，大幅提升传输可靠性
2. **DashScope compatible-mode**：通过 OpenAI 兼容格式调用国内模型，接口标准化
3. **`/no_think` 指令**：关闭 Qwen3.5 的思考模式，减少延迟和 token 消耗（max_tokens=80 即可满足）
4. **65 秒超时**：模型响应可能较慢，足够的超时避免误判失败
5. **多层容错解析**：JSON 解析失败时回退到文本关键词匹配，容错时置信度设为 0.7
6. **保留 Base64 调试接口**：即使 OBS 不可用，也能通过测试程序验证 AI 识别功能
